## 1. 文脈

### 1.1 ユーザー動機（原文要約）

当初は **観測登録報酬** · **マーケット 8% の再分配** · **開発報酬** を個別に設計しようとしたが複雑すぎた。  
→ **3 軸に集約**し、「**判定基準を決めれば終わり**」という方針に簡略化。

### 1.2 ユーザー提案 — 貢献度 3 種（3 軸）

| 軸 | 日本語 | 例（ユーザー言及） |
|----|--------|-------------------|
| **A** | **資本貢献度**（capital / money） | マーケット売上 · **8% システム維持費税**の支払い（支払額 1:1 → 資本 pt · 30 日超未払い → #08 カルマ Fib ペナルティ · §6.7） |
| **B** | **研究貢献度**（research） | **観測登録** · 論文等（ユーザーの本来意図） |
| **C** | **開発貢献度**（development） | GitHub + 掲示板（愚痴/改善→採択/解決）· fork ロイヤルティ · システム更新者 — §6.6 |

### 1.3 ユーザー提案 — メカニクス

| # | ルール（ユーザー案） | 備考 |
|---|---------------------|------|
| M1 | 各軸は **貢献源を独立追跡** | 軸ごとに ledger / カウンタ分離 |
| M2 | 各軸 **100 ポイント到達 → PT コイン 1 枚** | 初回ミント閾値（**Human Go 確定**） |

## 5. #08 / #14 REQ への影響 — gap か supersede か

| 機能 | 判定 | 理由 |
|------|------|------|
| **#14 貢献度** | **拡張（supersede ではない）** — 採用時は **REQ CR** | コア FR（非負 · R2 append · 100→PT）は残せる。**軸フィールド · decay · Fib 閾値**を追記。単一 score を **3 snapshot** に拡張 |
| **#08 カルマ** | **原則 gap（触れない）** | 8% **未払いペナルティ**（Fib Δcount）は確定済み。**お金軸ポイント**を 8% **支払い**と連動させるなら #06/#14 側の CR。**カルマ式は supersede しない** |
| **#06 マーケット** | **gap + 横断 CR 候補** | 8% の **経済意味**（義務 vs 貢献ポイント源）を人間が先に決める必要 |

**結論**: 全面 supersede は **不要**。採用なら **#14 を主 CR** · #06 §11.7 クロスリファレンス · #08 は **ペナルティ軸として維持**。

### 6.2 PT ミント — 軸別独立（確定）

各軸で **独立** に PT をミントする。**3 軸合算ミントはしない**。

#### 6.2.1 用語

| 用語 | 定義 |
|------|------|
| **cumulative** | 当該軸の **累積貢献**（常に増加 · 減算しない） |
| **used_for_mint** | 当該軸で **過去ミントに消費した累積分** |
| **eligible** | `cumulative − used_for_mint`（次ミント判定にのみ使用） |
| **mint_count** | 当該軸で **既にミント済み PT 枚数**（`k` · 0 始まり） |
| **next_fib_index** | 次ミントに適用する Fib 系列の **添字 n**（1 始まり · decay 対象） |
| **next_threshold** | `Fib(next_fib_index) × 100` — 次の 1 枚ミントに必要な **eligible 増分** |

#### 6.2.2 Fibonacci 系列（実装式 · Q3 確定）

**標準 Fibonacci**（1 始まり添字）:

```text
Fib(1) = 1
Fib(2) = 1
Fib(n) = Fib(n−1) + Fib(n−2)   （n ≥ 3）
```

**閾値増分**（PT 第 n 枚のミントに消費する eligible 量）:

```text
threshold_increment(n) = Fib(n) × 100
```

**系列（連続 · 5 枚目以降もリセットなし）**:

```text
100, 100, 200, 300, 500, 800, 1300, 2100, 3400, …
```

**状態初期値**（軸ごと）:

```text
mint_count       = 0
used_for_mint    = 0
next_fib_index   = 1
next_threshold   = Fib(1) × 100 = 100
```

#### 6.2.3 ミントアルゴリズム（疑似コード）

```text
function try_mint(axis):
  while eligible(axis) >= next_threshold(axis):
    k = mint_count(axis) + 1          // 今回ミントする PT 番号（1-based）
    cost = Fib(k) × 100               // = threshold_increment(k)
    assert cost == next_threshold(axis)

    used_for_mint(axis) += cost
    mint_count(axis) += 1
    eligible(axis) = cumulative(axis) − used_for_mint(axis)

    next_fib_index(axis) = mint_count(axis) + 1
    next_threshold(axis) = Fib(next_fib_index(axis)) × 100

    emit PT_minted(axis, k, cost)
```

**不変条件**:

- ミント直前: `eligible ≥ next_threshold`
- ミント直後: `used_for_mint` が `threshold_increment(1..k)` の和と一致
- **cumulative は減らさない** · **eligible はミント時のみ減る**（`used_for_mint` 増加による会計上の減）

**例 — 単軸で 5 枚/月**:

| ミント # k | `Fib(k)×100` | ミント後 `used_for_mint` |
|------------|-------------|-------------------------|
| 1 | 100 | 100 |
| 2 | 100 | 200 |
| 3 | 200 | 400 |
| 4 | 300 | 700 |
| 5 | 500 | **1200** |

→ 5 枚ミント = 当該軸 **1200 pt 消費**（eligible 会計上）

**例 — 150 cumulative · 1 枚ミント済み**:

- `used=100` · `eligible=50` · `next_fib_index=2` · `next_threshold=100` → **あと 50 必要**

**例 — 1500 cumulative · 1200 used · 5 枚ミント済み**:

- `eligible=300` · `next_fib_index=6` · `next_threshold=800` → **あと 500 必要**

#### 6.2.4 月次 decay（確定 · Q1/Q2）

**境界**: **UTC 暦月** — 各月 **1 日 00:00:00 UTC** で新期開始。UI は JST 等で表示可。

**軸別独立**: 3 軸それぞれ **独立** に decay 判定。他軸のミント有無は影響しない。

**ルール**（期 `M` = UTC 月 `[M_start, M_end)`）:

```text
function on_utc_month_boundary(axis, month M):
  if no PT_minted on axis during M:
    next_fib_index(axis) = max(1, next_fib_index(axis) − 1)
    next_threshold(axis) = Fib(next_fib_index(axis)) × 100
  // cumulative · used_for_mint · eligible は不変
```

**降格例**（当該月ミントなし · 同一軸）:

```text
800 → 500 → 300 → 200 → 100 → 100 → …（以降 100 で停止）
```

**下限（Q2 確定）**: `next_fib_index` は **1 未満にしない** → `next_threshold` 最小 = **`Fib(1) × 100 = 100`**

**persist 例**: `eligible=300` のまま threshold が 800→500→300 に decay → **追加獲得なしでミント可能**

| `system_maintenance_tax_unpaid` | —（カルマ） | 既存 #08 イベント · **資本 pt 加算なし** |

**明示的にやらないこと**: 維持費税プールの **再分配** · 支払いとペナルティの **相殺**

### 6.7 システム維持費税 — lifecycle（Q4 refined 確定 · 2026-07-05）

> **意図（ユーザー原文）**: 「利益を得た — システム維持に貢献せよ」  
> **名称**: **システム維持費税**（8% · `platform_fee_percent_bps=800`）— #06 §11.7 cross-ref 先  
> **#08 カルマ / #14 資本 pt は別システム** — 相互減算なし（§6.3 · H1）

#### 6.7.1 計上（accrue）

| 項目 | ルール |
|------|--------|
| **トリガー** | **取引成立**（#06 §11.0.1 — 配送完了 + 評価確定） |
| **義務者** | **売り手** |
| **金額** | 売上 × **8%** = 維持費税 **負債**（liability） |
| **例** | 売上 **10,000** → 維持費税 **800** が計上 |

```text
on_trade_completed(sale_amount):
  liability = sale_amount × 0.08
  due_at    = trade_completed_at + 30 days   // 支払期限（grace 終了）
  emit system_maintenance_tax_accrued(liability, due_at, trade_ref)
```

#### 6.7.2 30 日猶予（grace）

| 項目 | ルール |
|------|--------|
| **起点** | 取引成立タイムスタンプ（§11.0.1） |
| **猶予** | **30 日間** — この間は **カルマペナルティなし** |
| **UI** | 振込案内 · 残日数 · 維持費税額（GMO 照合 · #23） |

#### 6.7.3 分岐 — 期限後（due_at 経過）

```text
function on_maintenance_tax_due(trade_ref):
  if fully_paid(trade_ref):
    // §6.7.4 支払い分支 — 既に処理済みなら no-op
    return
  else:
    // §6.7.5 未払い分支 — #08 カルマ
    start_karma_fib_penalty(trade_ref)   // 月次 Δcount · Fib 系列
```

| 分支 | 条件 | 処理 | ドメイン |
|------|------|------|----------|
| **A · 支払い** | `due_at` 前後を問わず **全額消込** | 支払額 **1:1** → `capital` cumulative（800 支払 → **800 資本 pt**）· ペナルティ **停止**（以降の Fib Δcount なし） | #14 |
| **B · 未払い** | `due_at` 経過 · 残債 > 0 | **fee_unpaid** · **月次 Fibonacci Δcount**（1,1,2,3,5,8,13,21,…）— #08 §5.1 | #08 |

**部分入金**: #06 §11.7.5 維持 — 残債 > 0 かつ `due_at` 経過なら分支 B · 全額消込で分支 A のみ。

#### 6.7.4 Fibonacci — 実装分岐（共有数学 · 別システム）

| 用途 | ドメイン | 系列 | 添字 |
|------|---------|------|------|
| **PT ミント閾値** | #14 貢献度 | `Fib(n) × 100` eligible 増分 | §6.2.2 · `next_fib_index` |
| **維持費税 未払い Δcount** | #08 カルマ | `Fib(n)` Δcount / 月 | #08 §5.1 · 未払い月 n |
| **免罪符価格** | #22 PT | 既存正本 | ADR-H-08 管轄外 |

```text
// 共有: 標準 Fibonacci（§6.2.2 と同一関数）
Fib(1)=1, Fib(2)=1, Fib(n)=Fib(n-1)+Fib(n-2)

// 分岐: 呼び出し元・スケール・ドメインが異なる — 相互に減算しない
capital_mint_threshold(n)  = Fib(n) × 100    // #14 · 報酬
karma_unpaid_penalty(n)      = Fib(n)          // #08 · ペナルティ
```

> **UX**: UI 文言で **資本貢献（報酬）** と **カルマ減点（ペナルティ）** を明示分離 — 同一グラフに混在表示しない。

#### 6.7.5 状態遷移（要約）

```text
取引成立
  → 維持費税 8% 計上（liability）
  → [0..30d] grace（ペナルティなし · 振込可）
       ├─ 全額支払 → capital pt 1:1 · DONE
       └─ due_at 超・残債>0 → fee_unpaid · 月次 Fib Δcount（#08）
            └─ 後日全額支払 → capital pt 1:1 · ペナルティ停止（既付 Δcount は戻さない）
```
