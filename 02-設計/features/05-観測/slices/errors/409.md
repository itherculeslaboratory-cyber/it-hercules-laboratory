# 05-MICRO-error-004 — HTTP 409（表示名競合）

- **owner**: auto
- **type**: error-code
- **inputs**: WorkOrder `05-MICRO-error-004` · `POST /api/solid-observation/commit` · [`エラーカタログ-v1.md`](../../エラーカタログ-v1.md) §409
- **acceptance**: 409 の発生条件 · detail メッセージ · UI 導線 · エラーカタログ行 · impl 引用 · テスト参照

## 概要

観測 feature #05 における **409 Conflict** は現状 **1 route · 1 条件のみ**: 固体観測 commit 時に **同一 owner 内で display_name（表示名）が既に使用されている**場合。命名 event（`naming/name_event` · INSERT ONLY）の一意性を HTTP 層で拒否する。brand テンプレ自動採番（`{series}-{year}-{seq}`）は **seq インクリメント**で 409 を回避する別経路（integration test 参照）。

## 発生 route 一覧

| route | auth | 409 条件 | detail |
|-------|------|----------|--------|
| `POST /api/solid-observation/commit` | session | `display_name`（または brand 生成名）が owner 内で既存 individual に割当済 | `同じ表示名が既に使用されています` |

### 409 にならない関連操作

| 操作 | 結果 |
|------|------|
| 異なる `owner_user_id` で同名 | **201**（owner スコープ外） |
| `brand_template_id` の seq 採番 | 連番でユニーク · 409 回避 |
| R2 no-overwrite / placement 409 | **別 feature**（#05 観測 route 外） |

## detail 形式

```json
{ "detail": "同じ表示名が既に使用されています" }
```

| 項目 | 値 |
|------|-----|
| HTTP status | `409` |
| detail 型 | string · 日本語固定 1 文 |
| 判定関数 | `_display_name_in_use(owner_user_id, display_name, exclude_individual_id?)` |
| イベント | 409 時は **name_event を書かない**（commit 全体が失敗） |

## 発生条件（詳細）

1. リクエストに `display_name` 非空、または `brand_template_id` から `resolved_display_name` が生成される。
2. `_display_name_in_use` が同一 `owner_user_id` の最新 `naming/name_event` を走査。
3. `new_name` が正規化一致 · かつ `exclude_individual_id`（今回 capture の individual）と異なる individual に紐づく → **409**。
4. 成功時のみ `naming/name_event` を append（`observation_solid.py:583-608`）。

## ユーザー向け文言（Web）

| 画面 | 表示 |
|------|------|
| `/observation/input/confirm` | commit 失敗 · `ApiError.message` → 「同じ表示名が既に使用されています。別の名前を入力するか、表示名を空にして自動採番してください。」 |
| input 表示名フィールド | 409 後は入力画面へ戻し **表示名を編集**（主導線 · やり直し） |
| done 画面 | 409 時は到達しない |

**UI 一般則**（カタログ §UI）: 409 は **やり直し導線**（フィールド修正 · 自動採番へ切替）を 1 主ボタン内に含める。
