## Tier 1 — 今日だけ目を通す（5 項目）

推奨に異論がなければ、下記 5 点だけ確認すれば Wave C 再開の判断材料は足ります。詳細は推奨v1 §1 を参照。

### 1. X-01 — Wave C スコープ **B**（#05 + #11 並列）

#05 は hook-001 PASS 済み。#11 は depth=0.26 の P1 ブロッカーで、Wave C 外に置くと M-083 GATE 前に再び詰まります。経済束（#06/#08/#14/#23）は §11.7 CR Go 後に追加するのが最短です。

### 2. F05-01 / F05-02 — 研究軸換算 **A（+5 / +3）**

hook-001 scorecard 94 は +5/+3 前提で AUDIT-PASS 済み。数値を変えると換算表・RTM・parity の再監査が発生します。D-CONTRIB-01 と #14 CR を同セッションで close する想定です。

### 3. X-11 — システム維持費税 **A**（#06 MICRO 前に CR Go）

ADR-H-38 §6.7 は確定済みですが、#06 REQ §11.7 は依然「8% 貢献費」表記です。#06 MICRO 前に名称・30 日猶予・資本 pt 1:1 を REQ へ反映しないと、経済 DET が旧用語のまま執筆されます。

### 4. X-04 — ScreenDef 正本 **A**（`screen-defs/*.json`）

M-052 · walkthrough · ui-parts-lab · #16 UIbuilder の二重正本を解消する横断決定です。Phase5/TS を正本にすると contributor が編集すべきファイルが不明確になり、mock binding が drift します。

### 5. F11-01 — #11 並列厚み化 **A**（M-082 と同時）

REQ 716 行に対し DET v3 186 行。U-MKT-DSP v1.1 は確定済みですが、API/schema/争いイベントの MICRO 未分解が depth ブロッカーです。#05 とファイル衝突がないため並列が exec-audit サイクルと相性良いです（F11-02/X-24 4 点 Go も同時推奨）。
