## 0. この文書の目的

IHL の設計資料は **ファイル数・版・配置が増えすぎた**ため、「どれが正本か」「設計書とは何か」がパスだけでは判別できない。

本憲法は **成果物ごとに 1 つの定義・1 つの正本パス・1 つの完成条件（Done）** を固定する。  
AI 執筆・DOC-REMED 工場・OSS contributor は **本憲法に反する書き方を禁止**する。

**v1.1 変更点（要約）**: M-010 反映 — §1 に **SCD / CMP / INF/RUN** 追加 · §2 執筆深度 + 移動早見表要約 · 詳細は [`V-MODEL-LAYERS-v1.md`](../../docs/reference/V-MODEL-LAYERS-v1.md) へ委譲。

**原則**

| # | 原則 | 意味 |
|---|------|------|
| C1 | **正本は 1 つ** | 同一トピックに複数 md を「同等正本」として置かない |
| C2 | **破棄禁止** | 情報は削除しない。統合・stub・アーカイブ move のみ |
| C3 | **層分離** | REQ / DET / 遷移 / UI / TEST / RTM / SCD / CMP / INF の責務を混ぜない |
| C4 | **凍結 REQ** | `01-要件/` の FR 本文は CR 以外変更禁止 |
| C5 | **retrofit 尊重** | 既存実装を削らない。文書が追いつく（IMPL-GAP） |
| C6 | **機械 GATE** | 人間の「完成」宣言より GATE PASS を優先 |

## 2. 層ごと — 書いてよいこと / 書いてはいけないこと / 執筆深度

### 2.1 責務早見（C3）

| 層 | 書く | 書かない |
|----|------|----------|
| REQ | FR/NFR · 受入基準 · 境界 | API path · OpenAPI · `data-testid` · 実装パス · compose 手順 |
| DET | 契約 · 状態 · エラー · retrofit | 新規 FR 捏造（OBS-GAP は CR 後可） |
| TRN / UI | ルート · 遷移 · ワイヤー | ビジネスルールの二重定義 |
| SCD | ScreenDef JSON · chunk/binding | transform ロジック · schema フィールド詳細 |
| CMP | 7 分類 · component 境界 | 画面 chunk 順 · CSS |
| TEST 4 層 | TC ID · 手順 · 期待 | FR の言い換え |
| RTM | トレース · status | `existing` 粉飾 |
| INF/RUN | profile · deploy · SwitchBot 経路 | API body · FR |

### 2.2 執筆深度（要約 · 詳細は V-MODEL-LAYERS）

| 層 | 執筆単位 | 行数/粒度目安 |
|----|----------|---------------|
| REQ | 1 FR = 1 意図 + 測定可能な受入 | 機能全体 **200–400 行**（#05 級の 1000+ 行は異常） |
| DET v3 | §3 = **1 route** · §2 = **1 フィールド** | REQ 行数 × **0.8–2.0 倍** |
| TRN | 1 walkId · 遷移辺 | 状態名 · トリガー · 遷移先 route |
| UI/MOCK | 1 画面 × **4 状態** | 主ボタン **1** · mock 参照 |
| TEST | UT/IT/ST/UAT 各層 | 1 関数 / 1 API / 1 walkId / 1 req_id |
| RTM | csv 行 | req_id ↔ test_case_id **100%** |
| SCD | 1 screen_id | 3–5 チャンク · binding は catalog 登録済みのみ |
| CMP | 1 分類 × 1 component 典型 | DET §2 または §5 に初出 |
| INF/RUN | 1 profile または 1 runbook 節 | [`DOCKER-PROFILES-v1.md`](../../docs/reference/DOCKER-PROFILES-v1.md) |

### 2.3 移動早見表（REQ に書いてしまったら · 要約）
