## 2. 段階1: 構造完全性チェック

必須フィールドの有無・単位の有無・観点辞書キーの使用確認(原典 段階1 相当)。

| id | 判定ロジック概要 | 入力フィールド | 合否基準 |
|---|---|---|---|
| **AIRV-S1-01** 必須フィールド充足 | purpose / perspectives(または conditions) / protocol / results / metadata の各フィールドが非空か、`filled` フラグが true かを機械的にチェック | `purpose.text`, `perspectives`(観測) / `conditions`(PaperSectionsV1), `protocol`, `results`, `metadata` の `filled` bool | 必須フィールド **100% filled** で合格。1件でも false があれば不合格 + 欠落フィールド名を列挙 |
| **AIRV-S1-02** 単位付与チェック | 数値観点(perspectives の値)ごとに、観点辞書(K1)で定義された `unit` に対応する `unit` フィールドがレコード側に存在するか突合 | `perspectives[].value`, `perspectives[].unit`, 観点辞書の `unit` 定義 | 数値型の観点は **全件 unit non-null**。unit 欠落があれば当該キー名を列挙して不合格 |
| **AIRV-S1-03** 観点辞書キー使用確認 | レコードの `perspectives` キー集合が観点辞書の登録キー集合の部分集合かを集合演算で判定 | `perspectives` のキー一覧, 観点辞書(分野別)のキー一覧 | 未登録キー **0件**で合格。未登録キーがあれば `custom_key: true` タグ付きレコードのみ許容し、それ以外は不合格 |
| **AIRV-S1-04** ID整合チェック | `internal_id` が発行済み(非null)、`canonical_id` が Wikidata Q番号形式(正規表現 `^Q[0-9]+$`)に合致するかを検証 | `internal_id`, `canonical_id` | 両方とも形式適合で合格。`canonical_id` が正規表現不一致なら不合格 |

## 3. 段階2: 欠損検出

同分野の類似レコードと比較し、重要観点の欠落をスコア化(原典 段階2 相当)。

| id | 判定ロジック概要 | 入力フィールド | 合否基準 |
|---|---|---|---|
| **AIRV-S2-01** 同分野出現頻度比較 | 同一 `canonical_id` 系統(`taxonomy` 上位が一致)の既存レコード群における各観点キーの出現率を集計し、閾値(既定 50%)以上のキーを「重要観点」と定義。自レコードにそのキーが欠けていれば欠損としてフラグ | 自レコードの `perspectives` キー集合, 同分野レコード群の観点キー出現頻度テーブル | 欠損スコア = 欠落した重要観点数 ÷ 重要観点総数。**既定閾値 30% 以下**で合格。超過時は欠損キーを優先度(出現率降順)付きで列挙 |
| **AIRV-S2-02** gaps.missing_keys 整合確認 | `PaperSectionsV1.gaps.missing_keys` が Paper Match(`POST /match`)由来の決定論出力と一致しているかを突合(DET-KN-5 の接続を検証。ここでは新規判定を行わず既存出力の**転記漏れ検出**のみ) | `gaps.missing_keys`, Paper Match レスポンスの `missing_keys` | 双方が完全一致で合格。差分があれば「gaps 節が Paper Match 結果を反映していない」として不合格 |

## 4. 段階3: 再現性チェック

手順の曖昧さ、条件不足、測定法の不整合を検出(原典 段階3 相当)。

| id | 判定ロジック概要 | 入力フィールド | 合否基準 |
|---|---|---|---|
| **AIRV-S3-01** 手順ステップ完備チェック | `protocol.steps` 配列が空でないこと、各要素が `action` / `duration` / `unit` 等の必須プロパティを持つことを検証 | `protocol.steps[]` | 配列長 ≥ 1 かつ各要素の必須プロパティが全件 non-null で合格 |
| **AIRV-S3-02** 校正情報チェック | 測定器を用いる観点(観点辞書で `requires_device: true` の観点)について、`metadata.measuring_device_id` と `metadata.calibration_date` が存在するかを検証 | `metadata.measuring_device_id`, `metadata.calibration_date`, 観点辞書の `requires_device` フラグ | 該当観点が1件でもあれば両フィールド non-null で合格。観点辞書に該当なしなら本チェックはスキップ(N/A) |
| **AIRV-S3-03** 曖昧表現検出 | `protocol` の自由記述フィールドを、既定の曖昧語辞書(「適量」「少し」「多め」「適宜」等)と単純文字列マッチし、該当があればフラグ | `protocol.*`(自由記述文字列フィールド) | 曖昧語マッチ **0件**で合格。マッチした場合は該当箇所(フィールド名+マッチ語)を列挙して不合格 |
| **AIRV-S3-04** 手順時系列整合チェック | `protocol.steps[].order`(または `timestamp`)が単調増加であるかを検証 | `protocol.steps[].order` / `timestamp` | 単調増加で合格。逆転・重複があれば不合格 |

## 5. 段階4: 整合性チェック

単位整合、値の範囲外検出、時系列の欠損・重複(原典 段階4 相当)。

| id | 判定ロジック概要 | 入力フィールド | 合否基準 |
|---|---|---|---|
| **AIRV-S4-01** 単位整合チェック | 各観点キーの `unit` が観点辞書定義の正規単位、または辞書の許容代替単位テーブルにあるかを突合 | `perspectives[].unit`, 観点辞書の `unit` / `allowed_units` | 全観点で単位一致 or 許容代替内で合格。不一致は換算前提が崩れるため不合格 |
| **AIRV-S4-02** 値域外検出 | 数値観点が観点辞書で定義された物理的妥当範囲(例: 温度 0–50℃、湿度 0–100%)内かを検証 | `perspectives[].value`, 観点辞書の `min` / `max` | 全件が範囲内で合格。範囲外の値があれば当該観点・値を列挙して不合格 |
| **AIRV-S4-03** 時系列欠損・重複検出 | `results` の時系列テーブルの `timestamp` 列に重複がないか、想定サンプリング間隔からの欠落(gap)がないかを検証 | `results.timeseries[].timestamp`, `metadata.sampling_interval` | 重複0件・欠落率が既定閾値(例 5%)以下で合格 |
| **AIRV-S4-04** canonical_id 整合チェック | `canonical_id` が `truth/canonical/mapping_event` に登録済みか、`taxonomy` 配列が canonical 層のキャッシュと矛盾しないかを突合 | `canonical_id`, `taxonomy`, canonical 層 `mapping_event` / `cache` | 登録済みかつ `taxonomy` が矛盾なしで合格。未登録の場合は「マッピング未確立」として不合格(要マッピング生成) |

## 6. 段階5: 統計的妥当性チェック

サンプル数、分散、基本統計、簡易仮説検定の適用可否(原典 段階5 相当)。

| id | 判定ロジック概要 | 入力フィールド | 合否基準 |
|---|---|---|---|
| **AIRV-S5-01** サンプル数充足チェック | `results` 内の観測サンプル件数が、観点辞書または分野設定の最小サンプル数 `n_min`(既定値 3)以上かを検証 | `results.samples[]`(件数), 分野設定の `n_min` | `n ≥ n_min` で合格。未満なら「サンプル不足」として不合格 |
| **AIRV-S5-02** 基本統計算出可否チェック | 数値配列に対し mean / std / variance が計算可能か(NaN 非含有、定数配列でないか)を検証 | `results.samples[].value`(数値配列) | NaN 0件かつ分散 > 0 で合格。定数配列(分散0)は「分散なし」として不合格 |
| **AIRV-S5-03** 外れ値検出 | IQR法(四分位範囲: Q1 − 1.5×IQR 〜 Q3 + 1.5×IQR の範囲外)で外れ値を検出 | `results.samples[].value` | 外れ値0件で合格。検出時は該当サンプルを列挙(不合格ではなく警告フラグ扱い) |
| **AIRV-S5-04** 簡易仮説検定 適用可否判定 | 対照群・実験群のデータが両方存在し、各群のサンプル数が `n_min` 以上かを検証(検定の**実施**はオプション、ここでは適用可否の判定のみを決定論で行う) | `results` の群分けキー(条件ラベル)ごとのサンプル数 | 両群とも `n ≥ n_min` なら「検定適用可」、いずれか未満なら「検定適用不可(参考統計のみ表示)」と分類。いずれも不合格扱いにはしない(情報フラグ) |

## 7. 段階6: 要約・改善提案生成(LLM = Sonnet)

段階1〜5の出力(スコア・欠損キーリスト・問題箇所リスト・統計指標)のみを入力とし、以下を**文章として生成する**。新たな判定・スコア計算・欠損キーの発見は行わない。

- 目的・主要結果の要約文
- 欠損観点の**提案文**(段階2で既に決定論コードが確定した `missing_keys` を、人間可読な文章・優先度説明に変換するのみ)
- 再現性問題箇所の説明文(段階3の不合格項目を平易な文章化)
- 条件リクエストの**下書きテンプレート文**(例:「湿度60%・餌量多め・密度低めで実施してください」— 段階2/4の欠損・不整合検出結果から機械的に埋めた変数を Sonnet が自然文に整形)

### DET-KN-5 との整合(重要)

`知の広場-仮採用-02-論文-v1.md` DET-KN-5 は「Paper Match → `gaps.missing_keys` / `score`」の接続を決定論コードで確立している。`DESIGN-subbrain-knowledge-layer.md` §5-5 も「`PaperSectionsV1` の『ギャップ節』に wiki の `open-questions.md` から**静的ヒント**を供給 — DET-KN-5 の枠内で LLM 層の価値を最初に見せられる場所」と明記する。

本チェックリストの段階6は、この境界を厳密に踏襲する:

- **LLM がやってよいこと**: 段階1〜5(決定論コード)と Paper Match(DET-KN-5)が既に確定した `missing_keys` / `violated_keys` / スコアを、要約文・提案文・条件リクエスト下書きという**静的ヒントの体裁**に変換すること。
- **LLM がやってはいけないこと**: どの観点が欠けているか・どの値が範囲外か・検定が適用可能かを LLM 自身が新規判定すること。これらは常に段階1〜5の決定論コードまたは既存の Paper Match ロジックが担う。
- 段階6の出力(要約・提案文)は**そのまま公開されない**。段階7で人間レビュアーが確認してから公開判断に組み込む。
