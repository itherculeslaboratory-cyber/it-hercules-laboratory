Phase A 抽出書の承認を受け、ver3（ゼロから再設計する次世代システム）の最終要件定義・設計書3種（日英）・開発計画（K4/W2）・動画量産パイプライン設計・wiki 統合設計・改善ループ/KPI 設計までを完成させる。**実装本体・YouTube 実運用は含まない**（Phase C 以降・別承認）。

## 7. 想定リスク

1. **外部調査の鮮度**: 2026-07 時点情報。B2 成果物に調査日を明記し、実装着手時に再検証条項を付ける。
2. **裁定保留の累積**: G2/G3 で保留が多いと B1 の確定範囲が痩せる → 保留要件は DRAFT 節に隔離し、確定分だけで B3 以降を進められる構成にする。
3. **W2 再開判断の複雑性**: ui-parts-lab-w2 資産・QUANTUM 1813シャードとの整合が必要 → B3 で「再開/作り直し/廃棄」の3案比較で提示。
4. **英語版の陳腐化**: 日英同時更新は運用負荷 → 日本語を正本、英語は各成果物確定時に一括生成と規約化。

## 8. 検証方法（批評家ゲート）

- 各成果物に: 仕様適合批評 / 出典実在チェック / intent 網羅チェック / 矛盾検査 の4点批評（Phase A と同型のワークフロー）。
- B1 は RTM カバレッジ 100% を機械検算。B4 は3種×2言語の相互整合を突合。B5 は「スクリプト→動画→投稿」のエンドツーエンド設計が図示されているかを合格条件とする。
- 通らないものは納品しない（思想⑤）。
