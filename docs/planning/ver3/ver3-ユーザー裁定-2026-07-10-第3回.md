## 7.2 の10件（原文と処置）

### 1. V3-FND-13（Kernel UUID ルーティング）→ **確定**

> kernel 化はその時の手段だっただけなので、よりよい手段があるなら不要です。

処置: Kernel UUID ルーティングは棄却。Next.js / ScreenDef / AppRoutes 方式で確定（V3-UIX-18 の ScreenDef SSOT と整合）。

### 2. V3-AIP-61（開発方式）→ **確定**

> グリーンフィールドで進める

処置: グリーンフィールド（ゼロから作り直し）で確定。第2回裁定の新 repo 方針（`it-hercules-laboratory_ver3`）と整合。保留解除。

### 3. V3-AUT-25（World Modeling OS / permissions マッピング）→ **委任に基づく AI 裁定・確定(修正)**

> 任せます。

AI 裁定: World Modeling OS は**独立機能としては ver3 スコープ外**。World→…→SubComponent の階層は**データモデル（思想E）としてのみ保持**し、ノード permissions の IHL ロール/カルマへのマッピングは第2波の該当設計時に確定する。
適用ルール・理由: R5（迷ったら保留・水増し承認をしない）— 独立 OS としての採用は根拠不足のまま水増し承認しない。データモデルとしての階層保持は既定の思想Eと一致するため確定できる。

### 4. V3-UIX-39（ナビ形態）→ **委任に基づく AI 裁定・確定(修正)**

> UX が良くなるならそれでいいです。任せます。

AI 裁定: 共通クロム（V3-UIX-28）を正とし、**モバイルは下タブ・デスクトップはサイドナビ**のレスポンシブ標準形を採用。最終形は Phase C UI 設計の実測（ウォークスルー）で確定。
適用ルール・理由: 委任条件が「UX が良くなるなら」であるため、業界標準のレスポンシブナビ形を基本線とし、実測ゲート（実機ウォークスルー）を残すことで条件を担保する。

### 5. V3-UIX-07（二版未整合）→ **委任に基づく AI 裁定・確定(修正)**

> 任せます。

AI 裁定: **§12.7（REFRAME 窄化）版を採用**。
適用ルール・理由: R-9（撤回台帳: 機能開発は Builder 外・GitHub に任せる）および V3-UIX-08（REFRAME 窄化）と整合するのは §12.7 版のみ。§④版は R-9 と方向が衝突するため採らない。

### 6. V3-FND-24（物理層 SSOT）→ **確定**（R2-only）

> R2-only（神域）とする　がよくないですか？どう思いますか？私は技術的にこれがよいと思うのですが。Postgres(Neon)/D1 は高いから捨てたでしょう？ DB 機能は kernel に移植して、R2-only で行ける。と思うのですが。私のシステム、リアルタイム必要ないし。

処置: **R2-only（神域）で確定**。常駐 DB（Postgres/Neon/D1）を SSOT にしない — 既定の ADR-V3-LAYER-01・V3-FND-02 と一致。検索・集計は投影層（Parquet/DuckDB 等、再生成可）で提供する。
注記: ユーザー発言中の「DB 機能の kernel への移植」について — DB 機能の移植先は Kernel ではなく**投影層**である（Truth = R2 append-only、投影 = 再生成可能な導出データ。この二層で DB 相当機能を賄う）。

### 7. V3-UIX-20（UI アーキ一本化）→ **確定**

> まあ、builder ができるなら何でもいいです。

処置: **ScreenDef SSOT 一本化で確定**（14Kernel 収束は棄却）。条件: ノーコード UIBuilder が ScreenDef 上で成立すること（V3-UIX-61 の 80/20 フロー）。

### 8. V3-OTH-13（文化圏）→ **委任に基づく AI 裁定・確定(修正)**

> 任せます。ここよくわからない。シンプルがいいんじゃない？

AI 裁定: 「文化圏」を全層横断の最上位概念としては**採用しない**。タグ＋コミュニティへ畳み込む（シンプル優先）。将来必要になれば投影層の派生概念として再導入可（**Truth スキーマには焼き込まない**）。
適用ルール・理由: 委任条件が「シンプルがいい」であるため最小構造を採る。Truth に焼き込まなければ後戻り可能であり、R5（水増し承認しない）とも整合。
