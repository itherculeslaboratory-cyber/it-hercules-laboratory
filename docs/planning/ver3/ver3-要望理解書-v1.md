## §0 読み替えの宣言 — このフィードバックで何を変えたか

あなたの言葉（2026-07-10）:

> ver3でやりたいことは、私の技術不足で実現できなかったものを、私の要件整理から作ってほしい。
> ver1やver2で不採用になったものは、いらないから不採用じゃなくて、技術不足で実現できなかったから不採用なのが多い。
> ver1,ver2は正解じゃなくて、ただの私の、実現したくてあがいた結果です。両方20点から、30点くらいですよ。

抽出書 v1 の前提を3点修正する:

| # | v1 の前提（誤り） | v2 で採る前提 |
|---|---|---|
| 1 | ver2 正本 = 最高信頼。「何が欲しいか」も ver2 文書を優先 | ver2 正本が正確なのは「何が決まったか・何が実装されたか」の記録だけ。**「何が欲しいか」の正本はあなた自身の言葉**（Keep 1,329・Copilot 601会話・Cursor 687セッション・intent） |
| 2 | 「ver2 で不採用・縮小」= 優先度低 | **不採用 ≠ 不要**。差分レポートの「落ちた機能」D-01〜D-15 は欲求の本体候補として再浮上。例外は「あなた自身が撤回したもの」だけ（§4） |
| 3 | スコアに (6−実装難易度) の加点 = 簡単なものほど上位 | **廃止**。「技術不足で実現できなかったものこそ作りたい」に真逆だった。v2 は 重要度 = 欲求強度 × 事業価値 × 依存関係、実装難易度は順位に使わず「2026年の実現手段」という別欄にする |

裏づけの数字: 統合レジストリ 710 エントリのうち **453件（64%）は ver2 のどの文書にも着地していない「会話・メモの中だけの欲求」**だった（pure_conversation 計量）。ver2 は要求の1/3しか受け止めていない — 「20〜30点」という自己評価とデータが一致する。

## §1 一文の理解（ここがズレていたら全部やり直します）

> あなたが作りたいのは、**「ヘラクレスの世界に存在しなかった『再現性のある観測データ』を、写真1枚から誰でも作れるようにし、全ブリーダーを研究者に変え、観測 → 論文 → 経済 → 文化のすべてが消えない記録（R2 append-only）の上で回り、全部品が fork でき、AI が動画と知識を毎日量産して宣伝も学習も自走し、あなたが居なくなっても・ユーザーが増えなくても10年回り続ける『文明OS』**」。
> ver1 も ver2 もその部分実装であり、当時届かなかった部分 — 動画量産・記憶OS・Builder・ツイン・時代エンジン — こそが本体。

そしてもう一つ、開発のやり方そのものへの欲求:

> **「私は一人で全部できない。だから要求を明確にするのは私、設計・実装・検証は AI の物量（司令塔+チーム編成+批評家）でやる」** — ver3 は成果物だけでなく、この開発体制ごと作ることを含む。

## §2 欲求台帳 — 12テーマ（欲求の強い順ではなく、物語の順）

各テーマ: **欲しいもの**（あなたの言葉を最大限使用）/ 欲求の強さ（言及ソース数・期間・経路）/ なぜ当時できなかったか / 2026年の今なら / ver3 での扱い案。

### 1. 観測文明コア — 「写真1枚で、mm精度で、全部記録できるシステムが無かった」

**欲しいもの**: 『写真1枚撮影するだけで、mm単位の精度で、色も、光度や湿度、温度、全て取得し記録できるシステム』。存在しなかったから自作するしかなかった — これが文明OSの動機のゼロ章。『使用者の声は使うつもりない。だってデータの再現性がないもん』— 経験談と噂への対抗として、全国の参加者がスマホで同一品質の画像を撮れる標準撮影チャンバー、CIELAB/ΔE で10年比較可能な色彩規格（BPCMS）、『写真は色補正しない。そのままの事実 + 色基準の写し込みで後から再解析』、理想像クエリで近さ検索。
**強さ**: 52ソース / 2026-03〜07 の4ヶ月・全6経路で反復。
**当時の壁**: 治具の物理製作・色補正パイプライン（射影変換+測色）・類似検索の実装力。similarity-search は 501 stub のまま、rerank の色/サイズ/血統成分は未配線、埋め込み次元も 384 vs 768 で不整合のまま。
**今なら**: ColorChecker 検出→Lab 変換は colour-science + OpenCV の確立領域。DINOv2 + faiss は成熟。端末側 ONNX で従量課金ゼロとも整合。
**ver3**: **コア**（観測パイプライン継続）+ 第2波（チャンバー実機・BPCMS strict。次元統一 ADR が前提、治具は人間裁定）。

### 2. 論文OS / 科学OS — 「全てのブリーダーを研究者にしたい」

**欲しいもの**: 『私は一人で研究全部できないから、皆で物量で攻める』。論文は書くものではなく、仮説とデータと結果があれば**自動で生成される**もの（Living Paper）。『論文を数値化してベクトルにできるなら、足りてない観点もわかるようになるよね？』。『こんな条件で育ててくれ』と条件リクエストを出せばブリーダーがデータを出すだけで追検証が完了し勝手にグラフに追加される。『論文が有料で読めない…発展の邪魔。許せない』への怒りから、観測データは CC0 推奨のオープン API で公共インフラ化。世界の巨大データは持たず Wikidata QID + GBIF/NCBI 参照で「使われた瞬間だけ発行」。
**強さ**: 71ソース / 2026-02-23（最古の会話）〜07-10 の全期間・全7経路。**事実上プロジェクトの背骨**。
**当時の壁**: ver1 で3週間一括生成を試み、あなた自身が『機能が紐づかない』と破綻を発見 — end-to-end の配線力。
**今なら**: AI査読は「決定論5段 + LLM 1段」（あなたの設計そのまま）がエージェント分業で配線可能。embedding で観点ギャップ検出も成立。
**ver3**: **コア第1波**（Paper Match + 6節論文 + 引用）。第2波: AI査読・ベクトルgap検出・条件リクエスト・オープンAPI。

### 3. 自己進化する記憶OS / wiki 統合 — 「文明の図書館」

**欲しいもの**: 会話ログ・観測・掲示板・論文・設計書を『全部食わせる』と AI が要約・タグ・embedding して自動構造化し、ベクトルDBを持たず R2 だけに貯まり続ける記憶OS。毎回ゼロから再検索する RAG は重いので、一度蒸留した知識を wiki（サブブレイン）に蓄積して更新し続ける。『これ階層構造にできないかな？…大きいWiki…精度をよくして、なぜか安くならないかな？』（2026-07-09 — intent の「小wiki→大wiki」はこれ）。属人化を消し『設計書・コード・掲示板・意図・歴史・fork系譜を1クエリで引ける』。
**強さ**: 75ソース / 408ヒット / 全7経路 — **最頻出**。keep-b15 のラベル『🌌終わっちゃったんだぁ』は技術不足で一度心が折れた痕跡（欲求の撤回ではない）。
**当時の壁**: RAG の重さを軽くする実装力。embedding 基盤未定義のまま断念。
**今なら**: ver2 の docs/knowledge（決定論梯子 + 蒸留、読解量 1/6.8 の自己証明済み）が既にこの思想転換の実装。拡張するだけ。
**ver3**: **コア**（既存サブブレインを本体に昇格・全ソース ingest 対応へ拡張）。

### 4. 自然淘汰経済 — 「10万詐欺より3回正直取引の方が得」

**欲しいもの**: 運営が資金を預からない・裁かない非エスクロー P2P 市場。主観評価でなく、行動が全部記録されるカルマ（減るだけ・時間経過でしか回復しない信用の残高）と、金で買えないプラチナコイン（『通貨ではなく文明の勲章。義務を果たして得た権利』）。手数料はヤフオク10%より必ず安い8%。免罪符・減点・mint は全部フィボナッチで自己抑制。『文明OSは嘘を暴かない・事実を並べるだけ』。
**強さ**: 80ソース — **出現ファイル数で全テーマ中1位**。2026-02-27『カルマにしてやろうかな』が初出。
**当時の壁**: 技術的不可能ではなく「台帳+状態機械+フィボナッチ+検索を一人で同時実装する量」。GMO が Webhook 非提供で本番が詰まった。
**今なら**: 純関数群 + R2 台帳は コーディングエージェントの得意分野。GMO はポーリング照合で代替（実鍵投入だけ人間ゲート）。
**ver3**: **コア**。ver1 の勲章思想（インフレ絶対禁止・上流10%還元・残90%消滅）を明示継承するかは人間裁定（§5）。

### 5. コンポーネント文明 / OSフォーク — 「R2 だけ神域、あとは全部 fork 可能」

**欲しいもの**: 全部を USB や Docker みたいに差し替え可能な部品にする。AI 側の共通規格が MCP なら、データ側の共通規格が C-USB。『他人の文明を丸ごと fork → ローカル改造 → 再公開』。全データに系譜（uuid/parent/lineage）。『fork すると強くなる』文明。あなた自身が「不可侵のコア思想2点」の一つと明言。
**強さ**: 40ソース・全7経路・4ヶ月連続。
**当時の壁**: 万物統一の部品契約を仕様にも実行環境にも具体化できなかった（C-USB スキーマ未定義・fork 隔離実行が言及止まり）。
**今なら**: 「1部品 = 1ディレクトリ（manifest/run/tests/README）」の薄い契約 + WASM サンドボックス + GitHub PR/Actions + R2 lineage で成立。MCP の標準化で「C-USB = データ側規格」の対比がそのまま実装できる。
**ver3**: **コア**（fork 文化・薄い部品契約・lineage）+ 第2波（OS 丸ごと fork・政治制度 permissions）。

### 6. Builder / UI-as-data — 「全ての人にとって使いやすいUIは無理。だから Builder が必要」

**欲しいもの**: UI をコードでなくデータ（ScreenDef/JSON）として扱い『できるだけコードを書かないで済む』。『全部の UI を自然言語で作られるプロンプトが欲しい』— 大構造は自然言語、細部はドラッグ。全画面に説明・愚痴・ビルダーの導線があり、使いづらければその場で直して保存・即反映・fork。テンプレ1箇所変更で全画面のデザイン一括伝播。
**強さ**: 73ソース / 2025-11〜2026-07 — **最も執拗に戻り続けたテーマ**（conv399 で「完成版」を数十回書き直し）。
**当時の壁**: OSS スタック未収束（tldraw↔GrapesJS↔Konva を往復）・自然言語→UI 生成がキーワードパーサ止まり・15編集モードへのスコープ膨張。『3週間でリリースできなかった』（2026-03-23）。
**今なら**: LLM の構造化出力で自然言語→ScreenDef 生成・差分 patch が安定して回る（v1/v2 を潰した本丸が解消済み）。ScreenDef 正本化は cursor 2026-07 で着手済み。
**ver3**: **コア**（UI-as-data 基盤）+ **第2波の主役**（自然言語→ScreenDef）。「配置+デザイン+紐づけに限定」はあなた自身の設計判断（H-01=B）なので維持。

### 7. 動画自動量産ライン — 「週1回の作業で毎日投稿」

**欲しいもの**: 文明OSの思想・開発の苦労・不透明性への不満を「ネタ」に、台本→画像→音声（ゆっくり/VOICEVOX）→字幕→合成→サムネ→自動投稿の1本ライン。投稿スタックに溜めて『私は一週間に一回作業するだけで毎日投稿が可能』。ただし丸投げは望まない —『分割点で人間が手を入れて手垢がつく。それが魂になる』。OK/NG とその理由も貯めて次回に反映。数字を追わず『私の価値観>世界観>一貫性』。
**強さ**: 28ソース / 2026-03-10〜07-10。一度縮小（Twin 方式廃止）→ 2026-07-10 intent で再点火。**Keep ラベル「1.やること 動画」52件**。
**当時の壁**: n8n + ローカルLLM(8GB GPU) + ffmpeg の手組みが実装力超過。『一日で20ドルかかった』とコスト破綻。ツイン掛け合い台本が破綻。著作権・自動投稿の法務未整理。
**今なら**: エージェント編成で台本、TTS API、動画生成 API or ffmpeg、Workers + 投稿 API でスタック投稿 — 大半が既製部品。
**ver3**: **第2波コア**（観測基盤の直後に最優先着手）。公開ボタンは初期は人間ゲート、著作権・コスト暴走は裁定必須。

### 8. デジタルツイン — 「AI のセリフは私は考えません」

**欲しいもの**: 自分の写像『IT.Hercules.Laboratory』と案内 AI『さくら』の二体で、掛け合いの台本・動画をログから自動生成して発信。人格はプロンプトで作らない —『余計な味付けはしたくない。思想的に美しくしたい。歪になる』— チャット/行動/判断ログ・OK/NG 差分・毎年の価値観リストから6層で自然に育てる。SoulProfile で声のブレを防ぐ。将来は誰もが自分の Twin を持てる Twin Factory。
**強さ**: 27ソース / 約2.5ヶ月の執着。
**当時の壁**: 二体に自然な会話をさせるオーケストレーション。あなたは 2026-05-31 に『間違っていた』と方式を撤回した — が、**撤回したのは実装方式で、二体発信という欲求本体ではない**（2026-07-10 の intent で動画量産と共に再浮上）。
**今なら**: マルチエージェント（各 Twin を別エージェント化）+ ログ RAG 接地で、当時「難しい」の中核が埋まる。
**ver3**: **実験枠 + 人間裁定** — どの形で蘇らせるか（方式差し替えの上で opt-in 発信モジュール）はあなたの裁定必須。

### 9. 時代エンジン / 文化可視化 — 「時代は回るから」

**欲しいもの**: 四半期ごとに文明を丸ごと『時代アーカイブ』として保存し『2026年3月時点の自分の文明を再現』できる。2時代の diff 比較・優れたものを過去から現在へコピー。記録→可視化（8軸ダッシュボード）→予測の3層。『時代は回るから…30年分ぐらい蓄積したら、勝手に AI で予測して回せるんじゃないかな？』（文化の気象予報士）。
**強さ**: 22ソース。A60-A95 と番号まで確保し MANIFESTO に昇格していた。
**当時の壁**: スナップショット基盤（イベントソーシング）自体が未完 + 予測の縦断データ不足（コールドスタート）+ 4D 演出の優先度落ち。
**今なら**: append-only 基盤の上のマニフェスト/ポインタとして巻き戻しは素直に成立。可視化は標準的 dataviz。予測だけはデータが貯まるまでヒューリスティック + 人間判断。
**ver3**: **第2波**（スナップショット復元・可視化）+ 実験枠（周期予測）。

### 10. 全自動運用 / 改善ループ — 「Output の反応が Input に戻る」

**欲しいもの**: 観測・ログ・掲示板・再生数・いいねを全部 R2（データの胃袋）に入れ、自律成長ループを回す。夜の安い時間にバッチで論文の種を生成し『朝6時に文明研究新聞』。外部ツールは UCC（文明OSの USB ポート）で接続。ただし完全無人ではない — 『AI 判断への同意率9割超で初めて基本部分を自動化し、人間は迷う1割だけ相手にする』。ワンクリック全自動は禁止（あなた自身の不変ルール）。
**強さ**: 82ソース / 2025-11〜2026-07 — **期間・経路数で最大**。
**当時の壁**: 一人で保守できるオーケストレーションに落とせなかった + API コスト破綻 + cron 収集の法務不安（能動方式へ自主後退）。
**今なら**: エージェントワークフロー（今この Phase A を回している仕組みそのもの）+ Workers cron/Queues + analytics API。UCC の答えは MCP。
**ver3**: **コア**（改善ループ・harvest・エージェント運用は稼働中）+ 第2波（KPI 還流・無人定期配信）。

### 11. 透明性 / 属人化ゼロ — 「わさおレベルの理解に誰でも到達」

**欲しいもの**: 全部ガラス張り。『計算式も公開する。毎年プラチナコインで全ユーザーで投票して決めよう』。ランニングコストは /costs で全ユーザーが確認できる（ただし利益・銀行残高は個人事業主のプライベート — この線引きはあなたの中の葛藤として記録）。裁判は判例として参照・引用可能に R2 へ。そして最上位: 『知識の属人化を完全に消し、誰でも短時間で「わさおレベルの理解」に到達』『自分がいなくなってもデータが残る』。
**強さ**: 69ソース・全期間・全7経路。
**当時の壁**: 公開する対象そのもの（価格エンジン・判例 DB・図書館検索）を作りきれなかった。
**今なら**: usage API + append-only 判例 + サブブレイン検索で大半が既製。
**ver3**: **コア**（非機能の骨格として最も安全に厚くできる領域）。「核は非公開」→「全部 OSS」への転換（2026-06-30『コピーされても増えにくい』）はあなた自身の最新判断として採用。

### 12. AI 開発体制 — 「私は要求を明確にするだけ。設計も実装も検証も AI の物量で」

**欲しいもの**: 『実際の設計はすべて高性能 AI にさせたい』『計画すらあなたじゃなくて立てさせたい』。司令塔1体 + 1機能あたり5〜10体（要件/詳細/UI/実装/懐疑/監査/司令塔）を最大25並列、安い Auto は湯水・高性能は温存。成果物は必ず独立の批評家を通す —『批評家を通らないものは納品されない』『checkbox theater は許さない』。進捗は固定フォーマットのダッシュボードで一目。
**強さ**: 30ソース / 物量思想は 2026-03『皆で物量で攻めるぜ』から一貫。
**当時の壁**: 技術力ではなく**道具が存在しなかった**。2026-03 の巨大会話は AI 応答を手で貼り戻す1本チャット — 人間が唯一の配管だった。
**今なら**: ほぼそのまま実現可能（この Phase A 自体が 125 エージェント編成 + 批評家6レンズで走った実証）。
**ver3**: **コア**（開発体制そのもの）。

## §3 欲求強度の機械計量 — 抽出書 v1 の何が壊れていたか

全710エントリに desire_score（= 言及ファイル数 + 2×経路多様性 + 期間の持続性）を機械計算した結果:

- **pure_conversation（ver2 文書に未着地の生の欲求）: 453/710 = 64%** — ver2 が受け止めたのは欲求の約1/3。
- 現行 Tier と desire_score は概ね順相関（S平均14.2 > A 10.6 > B 7.3 > C 5.8）— 抽出書 v1 の順位は「全壊」ではない。ただし:

## §5 では、何を作る必要があるか — ver3 システム像（3層）

**第1波（コア = 文明OSの骨格）**: 観測パイプライン（5ドメイン・append-only・類似検索）/ 科学OS核（6節 Living Paper・Paper Match・引用）/ 記憶OS（サブブレイン拡張・全ソース ingest・小wiki→大wiki）/ 自然淘汰経済（カルマ・PT・非エスクロー市場・8%）/ フォーク基盤（1部品=1ディレクトリ契約・lineage・GitHub 一本化）/ UI-as-data（ScreenDef 正本 + ThemePack 一括伝播）/ 透明性（/costs・判例 R2・属人化ゼロ検索）/ AI 開発体制（司令塔+批評家。これは開発手段であると同時に成果物）。

**第2波（= 技術不足で落ちていた本体。ver3 の存在理由）**: 動画自動量産ライン（人間は分割点の OK/NG だけ）/ 自然言語→ScreenDef 生成 / 標準撮影チャンバー + BPCMS strict（次元 ADR 後）/ AI 査読6段・観点ギャップ検出・条件リクエスト / 時代スナップショット復元 + 文化ダッシュボード / KPI 還流・文明研究新聞 / OS 丸ごと fork。

**実験枠（人間裁定つき opt-in）**: ツイン二体発信（方式差し替え版）/ 文化周期予測 AI（データ蓄積待ち）/ 勲章経済の希少性設計（インフレ禁止・90%消滅）の復活範囲。

横串の不変条項（抽出書 §1 の5条項 + 追加7思想）はこの全部の下敷きとして変更なし — 今回のフィードバックで壊れたのは「順位」であって「思想の言語化」ではない、と理解している（ここも違ったら指摘を）。
