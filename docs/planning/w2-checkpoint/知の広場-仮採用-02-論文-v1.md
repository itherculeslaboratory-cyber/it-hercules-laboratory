## §0 メタ

### 0.1 この文書の役割

知の広場（`/knowledge`）の **3 柱**（掲示板 · 記事/ブログ · 論文）のうち、**論文柱**を W2 checkpoint で仮採用するための **REQ/DET/UI/TRN/OSS の横断たたき台**である。

- **正本階層**（矛盾時は上が勝つ）: REQ → DET → UI → TRN（[`W2-DESIGN-DOC-PROCESSING-v1.md`](./W2-DESIGN-DOC-PROCESSING-v1.md)）
- **本書の位置**: 正式な `02-設計/features/09-論文/` 各層の **代替ではない**。人間が本採用するまで **設計ゲート §14 実装禁止**は継続。
- **velocity 原則**: 論文は **完成品の重圧を外し、`in_progress` を一級**とする。LaTeX エディタ・査読 WF 本実装・Knowledge Graph は **Phase 1 対象外**（ADR-H-09 §4）。

### 0.2 論文柱のメンタルモデル（ユーザー向け 1 文）

> **「観測から始め、条件を埋め、試し、記録し、引用する — 途中のまま消えない研究ノート」**

掲示板の「話す」と論文の「検証する」は **入口・画面・主タスクを分離**する（[`07-09-24-コンテンツ導線・UX提案-v1-DRAFT.md`](../../../02-設計/E2E/07-09-24-コンテンツ導線・UX提案-v1-DRAFT.md) §A · 知の広場確定 2026-06-18）。

## §REQ 将来要件化 — `FR-PAPER-KN-*`

> **ステータス**: すべて **草案・未昇格**。本採用時に `01-要件/09-論文.md` §13 へマージ or `accepted_requirements.csv` 昇格。  
> **命名**: `KN` = 知の広場（Knowledge）柱。既存 `FR-PPR-*`（Match コア）· `FR-PAPER-*`（拡張）と **併記・衝突時は KN が UX/IA を、PPR が API コアを正本**とする（本仮採用の整理）。

### REQ-KN-00 優先順位（velocity 再掲）

ADR-H-09 昇格反映に従い、実装優先は次の順とする。

1. **進行中論文 + テンプレ（FR-PAPER-KN-01〜04）** — `in_progress` 一級 · 6 節 · 5 ステップ
2. **観測逆流 + Paper Match（FR-PAPER-KN-05〜07）** — 運ぶ · 不足キー可視化
3. **case チップ探索（FR-PAPER-KN-08）** — 後から探す（BBS 層）
4. **BBS 議論分離（FR-PAPER-KN-09〜10）** — 話す vs 検証する
5. **引用・公開ビュー（FR-PAPER-KN-11〜12）** — Phase 1 最小

**指標**: 論文数ではなく **research velocity**（追試・引用・データ追加の回転）。一周 **7〜9 クリック・往復ゼロ**（低コスト導線 §3）。

## §DET 詳細設計（仮）

### DET-KN-1 エンティティと ID

#### 1.1 `content_id`（正本キー）

```yaml
content:
  content_id: uuid          # 正本。API 互換で paper_id エイリアス可
  content_type: enum        # research_note | hypothesis | paper | replication_report | review
  status: enum              # in_progress | proposed | under_review | testing | supported | rejected | published
  actor_id: string
  created_at: iso8601
  updated_at: iso8601       # 表示用。Truth は event 列の最新
  case_chip: string | null  # 探索用ラベル（温度実験等）— BBS paper_case とはリンク可
  sections: PaperSectionsV1
  citations: [citation_id]
  match_refs: [match_id]    # Paper Match 履歴（append-only）
```

- **C-USB / CoreEntityBase**: `core` + `rag` 準拠は Phase 1 目標。W2 以前は `research/v1/` ファイル群で近似（詳細設計-v3 §2）。
- **`paper_id` 互換**: 既存 `GET /papers` の `paper_id` は `content_id` の短縮表示 or 1:1 マップ。

#### 1.2 status 遷移（`in_progress` 一級）

```text
[起票] ──▶ in_progress（research_note）
              │
              ├─〔仮説にする〕──▶ content_type=hypothesis（status は in_progress 維持可）
              ├─〔記録を追加〕──▶ sections / results append（status 不変）
              ├─〔試す〕────────▶ 観測ループ（画面遷移のみ · status 不変）
              └─〔論文にする〕──▶ content_type=paper · status=published（確認 1 ステップ）

BBS 議論は status を進めない（別 thread_id · FR-PAPER-KN-09）
```

- **下書き禁止**: `draft` をユーザー向けラベルに使わない。内部互換で `draft` があっても UI は **「進行中」** に統一（ADR-H-09 §1）。

### DET-KN-2 六節スキーマ `PaperSectionsV1`

低コスト導線 §4.1 · FR-PAPER-04「構造のみ Phase 1」と整合。

```yaml
PaperSectionsV1:
  purpose:          # 目的 — 何を明らかにするか（1 行〜短文）
    text: string
    filled: boolean
  hypothesis:       # 仮説 — P⇒Q
    text: string
    filled: boolean
  conditions:       # 条件（温度/湿度/餌等）
    temperature_c: number | null
    humidity_pct: number | null
    feed: string | null
    extra: object   # 将来 IoT / placement キー
    filled: boolean
  verification:     # 検証したいこと
    text: string
    filled: boolean
  current_phase:    # 現在のフェーズ（5 ステップの enum）
    step: observe | hypothesize | try | record | cite
    label_ja: string   # 表示: 観測 / 仮説 / 試す / 記録 / 引用
  gaps:             # 必要なデータ / ギャップ
    missing_keys: [string]    # Paper Match 由来
    violated_keys: [{ key, reason }]  # 将来 FR-PPR-02 完全化
    tags: [string]            # 〔不足〕表示用
    filled: boolean
  completeness_pct: number      # 0–100 · 完成度メータ（09t）
```

**美学テンプレ（文体スキン）**: `PaperSectionsV1` とは **別ファイル** `aesthetic_skin_id` で後追い（ADR-H-09 §4 · 本仮採用では未定義）。

**並行ケース**: 親 `content_id` に `child_case_id[]` を append-only でぶら下げ（温度 A/B/C）。子も `PaperSectionsV1` を持つ — 詳細は Phase 1 最小 1 ケース表示 + 「ケースを追加」CTA。

### DET-KN-3 Citation パス（append-only）

```text
world/research/content/{content_id}/events/{event_id}.json   # 節更新・status 遷移
world/research/citations/{citation_id}.json                  # 引用レコード
research/v1/{actor_id}/{match_id}.json                       # Paper Match（既存）
```

**Citation 最小スキーマ（仮）**:

```yaml
citation:
  citation_id: uuid
  from_content_id: uuid
  to_ref:
    type: observation | cross | content | external
    id: string
  section_anchor: purpose | hypothesis | conditions | verification | gaps | null
  created_at: iso8601
```

- **INSERT ONLY**（R2Engine · ADR-H-04 §8）: 節の「上書き」は新 event として追記。UI は最新 event の materialized view を表示。
- **BBS 抜粋引用**: `to_ref.type=external` + `board_thread_id` — 論文節への転載は **Citation リンク**とし、BBS 本文を複製しない（議論分離）。

### OSS-KN-2 QuartoReview（09t split）の適用範囲

- **借りるもの**: 編集画面の **二分割**（プレビュー | フォーム）、節アンカー同期、完成度の視覚化。
- **借りないもの**: Quarto `.qmd` コンパイル · LaTeX PDF 出力 · R/Python チャンク実行。
- **IHL 実装**: React フォーム + `PaperSectionsV1` JSON · プレビューは **プレーンテキスト + 条件表**（Phase 1）。

### OSS-KN-3 OSF SchemaBlock パターン

```yaml
# 登録例（仮）
schema_id: ihl-paper-sections-v1
blocks:
  - id: conditions
    required: [temperature_c]
    ui: conditions_form
  - id: gaps
    computed_from: POST /match
```

- 節単位で **独立バリデーション** → 完成度メータの根拠。
- OSF 本体連携（preprint 登録）は **Phase 2+**。

### OSS-KN-4 refhub / Zotero 型リスト

- **Citation パネル**: 著者・年・`content_id` / `observation_id` · 〔ジャンプ〕〔解除〕。
- Zotero の **コレクション UI** は参考のみ。同期 API は Phase 2。

### OSS-KN-5 Manubot 公開ビュー

- 入力: `PaperSectionsV1` + Citation 一覧から **ビルド用 Markdown を生成**（サーババッチ）。
- 出力: 静的 HTML（`KN-P-04`）。**ユーザーは HTML ソースを編集しない**。
- 既存 `apps/web` への組み込みは本採用ゲート後。

### OSS-KN-6 採用しないもの（明示）

## 付記 — 批判的レビュー（1 段落）

論文柱の仮採用は、**「Paper Match だけの論文」から「in_progress を恐れず書ける研究ノート」へ**の IA 転換である。velocity の敵は LaTeX と Dashboard であり、味方は **6 節テンプレ + 5 ステップ + 観測逆流 + append-only** である。W2 の最大ギャップは **mock（進行中論文）と実装（BBS スレ一覧）の不一致** — 本採用前に必ず解消する。case チップは ADR-H-07 どおり **探す**ため BBS に残し、**進める**ための UI は `/knowledge/papers/:id` に集約する。これにより「話す」と「検証する」が混ざらず、7〜9 クリック一周が設計上可能になる。
