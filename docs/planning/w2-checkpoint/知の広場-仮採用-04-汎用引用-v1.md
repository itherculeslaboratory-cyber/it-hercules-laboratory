## §0 メタ

### 0.1 目的

IHL 全体で **「あの観測・あの投稿・あの論文・あの人・あのタグ」を 1 クリックで参照し、本文に埋め込み、permalink で再現できる** 横断契約を定義する。

ADR-H-09 は「引用ワンクリック」を velocity の核とし、ADR-H-10 は `PostEvent.citation_refs[]` → 共有 `Citation` を採用済み。本稿は **UI・トークン・preview API・permalink・分離原則** を **知の広場（07/09/24）＋観測（05）** にまたがって一本化する **仮採用パッケージ** である。

### 0.2 用語

| 用語 | 定義 |
|------|------|
| **CiteRef** | 引用先を指す構造化 ID（union type）。Truth 層の `citation_refs[]` 要素 |
| **Citation** | append-only の引用イベント実体（`ihl/research/citation/` · ADR-H-04/10 共有。BBS 専用は作らない） |
| **cite token** | 本文中の機械可読マーカー `[ihl:cite type=id]` |
| **permalink** | 人間が共有できる安定 URL（`post_id` ベース） |
| **>>N** | スレッド内の **表示専用** アンカー（板内連番。permalink ではない） |
| **tombstone** | 非公開・削除済み引用先のプレースホルダ表示 |

### 0.3 ステータスとゲート

| 項目 | 状態 |
|------|------|
| 要件（§REQ） | 仮採用 — FR-CITE-* 草案 |
| 詳細（§DET） | 仮採用 — schema 正本は本採用時に YAML 化 |
| UI（§UI） | 仮採用 — W2 lab `BoardPost.onQuote` 拡張前提 |
| 遷移（§TRN） | 仮採用 — permalink 一覧 |
| 実装 Go | **不可**（設計ゲート 4 点 · 人間確定前） |

### 0.4 非スコープ（v1 仮採用でやらない）

- Knowledge Graph 可視化（ADR-H-09 Phase 2/3）
- 外部 DOI / PubMed / Crossref 自動メタ取得（将来 `type=external` 拡張枠のみ予約）
- OSS forum（Discourse）本体への cite 双方向同期
- リアルタイム共同編集中の cite 競合解決（last-write-wins も v1 対象外）

## §REQ — 機能要件（FR-CITE-*）

### FR-CITE-01 — Permalink（安定 URL）

**各 cite 可能エンティティは、認可範囲内で共有可能な permalink を持つ。**

| cite type | permalink パターン（正本） | 安定キー |
|-----------|---------------------------|----------|
| `observation` | `/observation/{capture_id}` | `capture_id` |
| `individual` | `/individuals/{individual_id}` | `individual_id` |
| `cross` | `/lineage/cross/{cross_id}` | `cross_id` |
| `content` | `/knowledge/articles/{content_id}` または `/knowledge/blog/{content_id}` または `/research/paper-match/{content_id}` | `content_id` + `content_type` |
| `post` | `/board/{board_kind}/{thread_id}#post-{post_id}` | `post_id`（スレッド内不変） |
| `thread` | `/board/{board_kind}/{thread_id}` | `thread_id` |
| `user` | `/profile/{user_id}` | `user_id` |
| `tag` | `/knowledge?tag={tag_slug}` | `tag`（正規化 slug） |
| `template` | `/observation/templates/{template_id}` | `template_id` |
| `market_listing` | `/market/listings/{listing_id}` | `listing_id` |

- permalink は **INSERT ONLY** の ID に紐づく。編集で URL が変わらない。
- Scope A（公開観測）は未ログインでも permalink 到達可（OBS-GAP-01 整合）。
- 非公開・権限外は **200 ではなく 404 または tombstone プレビュー**（§FR-CITE-09）。

### FR-CITE-02 — 引用ボタン（ワンクリック）

**各詳細画面・投稿カードに「引用」ボタンを常設する（ADR-H-09 クリックバジェット: 1 クリック）。**

| 画面群 | ボタンラベル（案） | 動作 |
|--------|-------------------|------|
| 観測詳細 | この個体を引用 | composer へ遷移 + prefill（既存 `cite_capture`） |
| 掲示板投稿 | 引用 | 返信 composer に cite token + mini-card 挿入 |
| 論文/記事/ブログ詳細 | 引用に追加 | 現在の編集先 or 論文板 composer へ |
| プロフィール | このユーザーを引用 | `@` ではなく cite（§分離原則） |
| タグハブ | このタグを引用 | tag cite token 挿入 |

- **1 画面 1 主ボタン**原則: 観測詳細では「この個体を引用」が primary（[`observation-capture-id`](../../02-設計/features/05-観測/slices/screens/observation-capture-id.md) 確定済み）。
- 掲示板投稿カードは secondary アクション（`BoardPost` の `onQuote` · 主導線は読む/返信）。

### FR-CITE-03 — cite_refs（構造化参照配列）

**投稿・Content 本文とは別に、機械可読な `cite_refs[]` を PostEvent / Content メタに保持する。**

- 本文に token があっても **cite_refs が正本**（token は表示用デュアル書き可）。
- `cite_refs[]` の各要素は §DET の `CiteRef` union に準拠。
- 重複 cite は **許可**（同一 `capture_id` を複数回引用可）。集計は Snapshot 側。

### FR-CITE-04 — User cite

**ユーザーを引用すると、プロフィール要約 mini-card が埋め込まれる。**

- `CiteRef { type: "user", user_id }`
- `@username` による通知・宛先指定とは **別チャネル**（§分離原則）。
- 表示: 表示名 · 貢献バッジ要約 · プロフィール permalink。
- ブロック / 非公開プロフィールは tombstone（§FR-CITE-09）。

### FR-CITE-05 — Tag cite

**構造化タグ（`tag_event` 正本）を引用可能にする。**

- `CiteRef { type: "tag", tag, tag_namespace? }`
- `#hashtag` 入力は **発見・フィルタ UI**（横断ハブ `?tag=`）用。tag cite は **根拠付き参照**（例: 「この観測に付いた `horn:large` を引用」）。
- tag cite の preview は **直近の付与件数・代表 capture サムネ 1 枚**（色補正なし）。

### FR-CITE-06 — Observation cite

**観測（capture）引用は研究 velocity の中核（ADR-H-09）。**

- 既存 PoC: `/board/paper?cite_capture={captureId}`（論文板 composer へ prefill）。
- 汎用化後: **任意の composer**（愚痴/改善/記事/ブログ）へ `?cite_observation={capture_id}` で prefill 可能にする（板ポリシーで制限可）。
- preview: サムネ · 種名 · 計測 3 項目要約 · 撮影条件テキスト（色補正なし）。

### FR-CITE-07 — Post cite

**掲示板投稿を `post_id` で引用する。**

- `CiteRef { type: "post", thread_id, post_id, board_kind? }`
- 引用時は **抜粋 + 著者 + permalink** の blockquote mini-card。
- `>>N` は本文表示用ショートカット（§FR-CITE-08）。**permalink は `post_id` のみ**。

### FR-CITE-08 — >>N（表示専用アンカー）

**スレッド内連番 `>>N` は板内スクロール用。外部共有・Citation 正本には使わない。**

- レンダリング時に `(thread_id, N)` → `post_id` を Snapshot 解決。
- クリック: 同一スレッド内 `#post-{post_id}` へスクロール（SPA）。
- コピー: ユーザーが `>>12` をコピーしても、共有 URL には **自動で `#post-{post_id}` を提案**（任意 UI）。

### FR-CITE-09 — Tombstone（非表示・削除済み）

**引用先が hidden / deleted / moderated のとき、本文は壊さず tombstone mini-card を表示する。**

- `CiteRef { type: "tombstone", cite_ref_id, reason, original_type? }`
- 表示文案例: 「この引用先は非公開になりました（理由: モデレーション）」
- **Citation イベントは削除しない**（INSERT ONLY）。新規 cite のみ拒否 or tombstone 化。
- Snapshot `citation_summary` は件数に tombstone を含め、詳細は reason 別カウント。

### FR-CITE-10 — Preview API

**未遷移のまま hover / composer 内で引用先要約を取得できる（§DET API）。**

### FR-CITE-11 — Cite token 本文埋め込み

**Markdown 本文に `[ihl:cite type=id]` を許可し、レンダラが mini-card に展開する。**

### FR-CITE-12 — 監査・C-Sync

**cite 操作は `usage_event_type=cite`（既存辞書）で記録可能（任意 Phase 1 · 推奨 Phase 1b）。**

- `target_type` / `target_id` = 引用先
- `context` = composer 画面 / board_kind / content_id

## §DET — 詳細設計

### DET-01 — CiteRef union type（完全仕様）

```yaml
# 仮採用 · 本採用時 cite_ref.schema.yaml へ昇格
CiteRef:
  oneOf:
    - $ref: '#/CiteRefObservation'
    - $ref: '#/CiteRefIndividual'
    - $ref: '#/CiteRefCross'
    - $ref: '#/CiteRefContent'
    - $ref: '#/CiteRefPost'
    - $ref: '#/CiteRefThread'
    - $ref: '#/CiteRefUser'
    - $ref: '#/CiteRefTag'
    - $ref: '#/CiteRefTemplate'
    - $ref: '#/CiteRefMarketListing'
    - $ref: '#/CiteRefTombstone'

CiteRefBase:
  type: object
  required: [type]
  properties:
    type:
      type: string
    label_hint:
      type: string
      description: 表示用キャッシュ（任意 · Snapshot 再生成可能）

CiteRefObservation:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, capture_id]
      properties:
        type: { const: observation }
        capture_id: { type: string, pattern: '^cap-' }

CiteRefIndividual:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, individual_id]
      properties:
        type: { const: individual }
        individual_id: { type: string }

CiteRefCross:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, cross_id]
      properties:
        type: { const: cross }
        cross_id: { type: string }

CiteRefContent:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, content_id, content_type]
      properties:
        type: { const: content }
        content_id: { type: string }
        content_type:
          type: string
          enum: [research_note, hypothesis, paper, review, article, blog, replication_report, research_gap, other]

CiteRefPost:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, thread_id, post_id]
      properties:
        type: { const: post }
        thread_id: { type: string, pattern: '^thr-' }
        post_id: { type: string, pattern: '^pst-' }
        board_kind:
          type: string
          enum: [complaint, improvement, paper, general]
        display_anchor_n:
          type: integer
          minimum: 1
          description: >>N の表示用 · permalink には含めない

CiteRefThread:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, thread_id]
      properties:
        type: { const: thread }
        thread_id: { type: string }
        board_kind: { type: string }

CiteRefUser:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, user_id]
      properties:
        type: { const: user }
        user_id: { type: string }

CiteRefTag:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, tag]
      properties:
        type: { const: tag }
        tag: { type: string }
        tag_namespace: { type: string, description: '例 horn · color · phase' }

CiteRefTemplate:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, template_id]
      properties:
        type: { const: template }
        template_id: { type: string }

CiteRefMarketListing:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, listing_id]
      properties:
        type: { const: market_listing }
        listing_id: { type: string }

CiteRefTombstone:
  allOf:
    - $ref: '#/CiteRefBase'
    - type: object
      required: [type, cite_ref_id, reason]
      properties:
        type: { const: tombstone }
        cite_ref_id: { type: string, description: '元 CiteRef の安定ハッシュ or citation_id' }

          type: string

```

**JSON 例（観測引用）**:


### DET-02 — post_id 発行規則

ADR-H-10 の `PostEvent.post_id` を Phase 1 実装に接続する。

| 項目 | 規則 |
|------|------|
| 形式 | `pst-{ulid}` または `pst-{uuid7}`（[`board_store.py`](../../libs/ihl/governance/board_store.py) の `_new_id("pst")` 想定） |
| 発行タイミング | `post_created` / `post_append` イベント書き込み **直前**（クライアント生成禁止） |
| 一意性 | グローバル一意（スレッド跨ぎでも衝突なし） |
| 連番 N | Snapshot 再生成: スレッド内 `created_at` 昇順で 1..N を付与。**Truth には保存しない** |
| 既存ギャップ | 現行 `board_store.append_post` は `post_id` 未発行 → **Step 2 で拡張必須** |

**移行**: 既存 JSONL に `post_id` 無し行がある場合、バックフィル Snapshot で疑似 `pst-mig-{seq}` を付与（イベント本体は改変しない）。

### DET-03 — PostEvent 拡張

ADR-H-10 契約への追記（仮採用）:

```text
PostEvent（拡張）
  post_event_id, thread_id, post_id, parent_post_id(nullable),
  event_type, actor_id, body_ref,
  citation_refs[](nullable),    # CiteRef[]
  cite_tokens[](nullable),      # 本文から抽出した token 列（監査用 · 任意）
  moderation_tag(nullable), reason(nullable),
  created_at
```

| event_type | cite 関連動作 |
|------------|---------------|
| `post_created` | `citation_refs[]` 初期値。各 ref について Citation INSERT（§DET-05） |
| `post_edited` | 新イベント。追加 refs のみ新規 Citation。削除は **tombstone 化のみ**（物理削除なし） |
| `post_cited` | （任意）他投稿が本投稿を引用したときのメタイベント · Snapshot 用 |
| `post_flagged` | cite とは独立（指摘 · ADR-H-10） |

**body_ref**: `ihl/board/bodies/{thread_id}/{post_id}.md` — 編集は新ファイル + 新 `body_ref`。

### DET-04 — Citation INSERT 規則

共有パス: `ihl/research/citation/`（ADR-H-10 §5 — BBS 専用 Citation 禁止）

```text
Citation:
  citation_id, source_type, source_id, target_type, target_id,
  citation_kind, cite_ref_json, actor_id, created_at
```

| フィールド | 値 |
|------------|-----|
| `source_type` | `post` \| `content` \| `comment` |
| `source_id` | `post_id` \| `content_id` |
| `target_type` | `CiteRef.type` と同型 |
| `target_id` | 主キー（`capture_id` / `post_id` / …） |
| `citation_kind` | `embed` \| `reference` \| `reply_quote` |
| `cite_ref_json` | `CiteRef` 全体の JSON シリアライズ |

**INSERT 条件（すべて満たすこと）**:

1. `actor_id` が `source` への書き込み権限を持つ
2. `target` が存在し、かつ **readable**（否则 tombstone preview のみ · Citation は `reason=permission_denied` で INSERT 可 — 監査用）
3. 同一 `(source_id, target_type, target_id, citation_kind)` の **重複 INSERT は許可**（append-only 研究履歴）
4. `target` が moderated hidden の場合: **新規 INSERT 拒否** · 既存 Citation は維持 · UI は tombstone

**研究板との接続**: 論文板 `paper_case=observation` スレッドからの観測 cite は `citation_kind=reference`。Content 本文への embed は `citation_kind=embed`。

### DET-05 — Preview API

```
GET /api/v1/cite/preview
```

**Query パラメータ**:

| param | 必須 | 説明 |
|-------|:----:|------|
| `type` | ○ | `CiteRef.type` |
| `id` | ○ | 主キー（`capture_id` / `post_id` / `user_id` / …） |
| `thread_id` | △ | `type=post` のとき必須 |
| `content_type` | △ | `type=content` のとき推奨 |

**Response 200** (`CitePreview`):

```json
{
  "type": "observation",
  "id": "cap-20260325-abc123",
  "title": "ヘラクレスオオカブト ♂ L3",
  "subtitle": "78.2mm · 2026-03-25",
  "thumbnail_url": "/api/v1/observation/cap-.../image?size=thumb",
  "permalink": "/observation/cap-20260325-abc123",
  "badges": ["Scope A", "色補正なし"],
  "status": "ok"
}
```

**Response 200 tombstone**:

```json
{
  "type": "tombstone",
  "id": "cap-removed",
  "title": "この引用先は非公開です",
  "status": "hidden",
  "reason": "moderated"
}
```

**認可**:

- Scope A 観測: 未認証 OK
- 非公開投稿: 404 or tombstone（板の readable 判定）
- レート制限: 60 req/min/IP（preview 専用 · self-hosted）

**実装方針**: **self-hosted** — 外部 oEmbed に依存しない（プライバシー · 観測 blob 認証整合）。

### DET-06 — Cite token 仕様

**正規表現**:

```text
\[ihl:cite\s+([a-z_]+)=([^\s\]]+)(?:\s+([^\]]+))?\]
```

**例**:

| token | 意味 |
|-------|------|
| `[ihl:cite observation=cap-abc]` | 観測引用 |
| `[ihl:cite post=pst-xyz thread=thr-123]` | 投稿引用（post は thread 省略不可） |
| `[ihl:cite user=20260325-ITHL-...]` | ユーザー引用 |
| `[ihl:cite tag=horn:large]` | タグ引用 |
| `[ihl:cite content=cnt-001 content_type=paper]` | 論文 Content |

**レンダリングパイプライン（仮採用）**:

1. Markdown parse（remark）
2. custom plugin: `ihl-cite` token → `<CiteMiniCard citeRef={...} />`
3. 同期: 本文保存時に `cite_refs[]` を token から再抽出し PostEvent と突合（差分は警告ログ）

**remark-github との役割分担**:

- `@user` / `#123`（GitHub PR 風）は **採用しない**
- remark-github は **外部 GitHub URL の autolink** のみ参考（IHL 内部 cite とは別レイヤ）

## §分離原則

### SEP-01 — @mention vs cite

| | @mention | cite（本機能） |
|---|----------|----------------|
| **目的** | 相手への通知 · 返信期待 | 根拠・出典の提示 |
| **UI** | composer で `@` トリガ（tiptap Mention） | 「引用」ボタン · mini-card |
| **Truth** | `notification_event`（将来） | `Citation` + `citation_refs[]` |
| **表示** | インライン `@名前` リンク | blockquote mini-card |
| **例** | 「@田中 見てください」 | 「この観測（cap-abc）によると…」 |

**禁止**: `@cap-abc` のような曖昧合成。観測は **必ず cite**。

### SEP-02 — tag_event vs #hashtag

| | `#hashtag` | tag cite |
|---|------------|----------|
| **目的** | 横断検索 · フィルタ | 特定タグ状態の根拠参照 |
| **Truth** | `tag_event` append-only | `CiteRef type=tag` + Citation |
| **UI 入口** | composer 自由入力 · ハブ `?tag=` | 「このタグを引用」ボタン |
| **集計** | `tag_aggregate` Snapshot | `citation_summary` |

**禁止**: `#horn:large` を tag_event の代替として書くこと（入力は UI 層で `tag_event` に変換）。

### SEP-03 — >>N vs post_id

| | `>>N` | `post_id` |
|---|-------|-----------|
| **安定性** | スレッド内のみ安定 | グローバル安定 |
| **permalink** | **不可** | **正本** |
| **用途** | 板内会話の読みやすさ | 引用 · 監査 · C-Sync |
| **実装** | Snapshot 連番 | PostEvent 発行時固定 |
